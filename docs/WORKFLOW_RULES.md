# 📘 Правила работы над проектом NANOREM MLM

Этот документ фиксирует договорённости по работе с кодом, чтобы избежать поломок и хаоса.

---

## 🔹 1. Главный принцип

Работаем МЕДЛЕННО, но НАДЁЖНО.

Не допускается:

* массовое переписывание файлов
* догадки без проверки
* изменения сразу в нескольких местах

---

## 🔹 2. Формат работы

Каждый шаг строго:

1. Посмотреть текущий файл
2. Проанализировать
3. Сделать МИНИМАЛЬНОЕ изменение
4. Запустить проект
5. Проверить результат

👉 Только после этого идти дальше

---

## 🔹 3. Работа с файлами

Запрещено:

* укорачивать файлы
* удалять код без причины
* переписывать файл “с нуля”

Разрешено:

* менять 1–2 строки
* добавлять точечные изменения

Всегда:

* использовать ПОЛНЫЕ файлы при изменениях
* сохранять весь существующий код

---

## 🔹 4. Перед изменениями

Перед любым изменением:

👉 СНАЧАЛА показать текущий файл
👉 потом только правка

Без этого изменения не делаются

---

## 🔹 5. Git и безопасность

Всегда иметь точку отката:

* использовать теги (checkpoints)
* не работать без возможности отката

Если что-то сломалось:

👉 использовать:

```
git reset --hard <tag>
```

---

## 🔹 6. Архитектура (важно)

Основное правило:

👉 Один Bot instance на всё приложение

Запрещено:

* создавать Bot() в разных местах

Правильно:

Application → application.bot → передаётся в сервисы

---

## 🔹 7. Ошибки

Если ошибка:

1. НЕ паниковать
2. НЕ менять всё подряд
3. посмотреть лог
4. найти точную причину
5. исправить минимально

---

## 🔹 8. Коммуникация

Перед любыми изменениями:

* объяснить что будет изменено
* объяснить зачем

Без этого — не менять

---

## 🔹 9. Главная цель

Не “сделать быстро”, а:

👉 сделать СТАБИЛЬНО
👉 без поломок
👉 с контролем

---

## 🔹 10. Рабочее правило

👉 1 изменение = 1 проверка

---

## 🔹 Итог

Работаем как инженерная система:

* без спешки
* без хаоса
* без угадывания
* только проверенные шаги

👉 Двигаемся только вперёд
