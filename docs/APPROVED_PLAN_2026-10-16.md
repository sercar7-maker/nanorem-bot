# NANOREM — утверждённый план от 16 октября 2026 года

Статус: бизнес-правила подтверждены владельцем в переписке 16.10.2026; реализация и проверки ведутся отдельно. Этот документ дополняет PROJECT_DECISIONS.md. При противоречии с прежними решениями по перечисленным ниже вопросам применяется это датированное дополнение. Остальные ранее утверждённые правила сохраняются.

## 1. Приглашение и закрепление клиента

До первой оплаченной покупки приглашение действует 30 дней с последнего перехода по партнёрской ссылке. Новая партнёрская ссылка заменяет предыдущее приглашение и запускает срок заново. После истечения срока без нового перехода покупка учитывается без приглашения.

Первая оплаченная покупка по действующему приглашению закрепляет клиента за соответствующим партнёром. Истечение срока приглашения после этого закрепление не отменяет. Если система узнаёт закреплённого клиента, повторные оплаченные покупки относятся к тому же партнёру, включая прямые заходы без ссылки. Закреплённый партнёр получает 20%, остальные четыре вышестоящие линии рассчитываются по действующему пятилинейному плану: 20%, 10%, 5%, 5%, 5%.

## 2. Клиент становится партнёром

Закреплённый клиент при вступлении в программу ставится в первую линию непосредственно под закрепившим его партнёром. Балансировка между ROOT к нему не применяется. Прежние клиентские покупки не пересчитываются; новые покупки учитываются по правилам для партнёра.

## 3. Балансировка между ROOT

В системе остаются ровно два постоянных ROOT. Вступающий без приглашения и ранее установленного закрепления автоматически размещается в первой линии непосредственно под ROOT с меньшим общим количеством партнёров во всей его структуре на всех уровнях. Объём продаж не влияет на выбор.

При равенстве количества партнёров выбор ROOT чередуется: при каждом следующем случае равенства очередь переходит другому ROOT. Это заменяет прежний выбор ROOT с большим id при равенстве, зафиксированный в PROJECT_DECISIONS.md, Q-3 и разделе 10. Исторические результаты тестов старого правила не подтверждают новое поведение.

Ручное назначение для этого сценария не требуется; новый ROOT не создаётся. Правило поздней реактивации под первоначальным ROOT этим решением не изменяется.

## 4. Административное вознаграждение владельца

Ежемесячное вознаграждение владельца составляет 5% от общей фактически оплаченной суммы покупок всего магазина за месяц, а не от отдельного ROOT. Включаются обе ROOT-структуры, клиенты, партнёры, гостевые покупки, продажи с приглашением и без него. База — реально уплаченная сумма после скидок и акций, а не цена до скидки.

Административные 5% начисляются отдельно от пяти партнёрских линий и не дублируются при наличии дополнительных позиций владельца. Это новое решение заменяет прежнюю неопределённость процента, общей базы и месячного периода в разделе 6 и Q-6 реестра. Неурегулированные финансовые вопросы перечислены ниже.

## 5. Дополнительные партнёрские позиции

Возможность иметь дополнительную обычную партнёрскую позицию распространяется на всех партнёров, не только на владельцев ROOT. Одна позиция занимает отдельное место в дереве и получает обычное вознаграждение с пяти линий под собой. Она не расширяет глубину начислений исходной позиции.

Один пользователь имеет один вход и один ЛК. Внутри ЛК позиции учитываются раздельно: непосредственный вышестоящий партнёр, нижняя структура, начисления, подписка и активность. Привилегии ROOT и административные 5% дополнительным обычным позициям не передаются.

Размещение обычной позиции владельца ROOT на шестой линии обсуждалось как пример. Универсальные условия открытия, количество позиций и алгоритм выбора места ещё не утверждены; произвольные значения не реализуются.

## 6. Подписки и компрессия

Для активности всех обычных позиций пользователь поддерживает отдельную действующую подписку на каждой. Активная подписка одной позиции не активирует остальные. К позиции с прекратившейся подпиской применяется компрессия по общим правилам программы. Остальные активные позиции владельца не становятся неактивными из-за этого. Исключения постоянных ROOT сохраняются и не распространяются на их дополнительные обычные позиции.

В ЛК по каждой обычной позиции показываются статус активности и дата окончания подписки. Ранее утверждённые пороги активности этим документом не изменяются.

## 7. Финансовый блок ЛК

Начисления показываются помесячно, раздельно по позициям. Для владельца предусмотрены колонки: месяц; по структуре ROOT; по дополнительной обычной позиции; административные 5%; итого. При дальнейшем согласовании количества позиций представление должно позволять раздельный учёт каждой из них.

Для обычного партнёра административная колонка не предусмотрена. Месячный итог равен сумме его партнёрских начислений по позициям. У владельца в итог дополнительно включается административное вознаграждение. По структуре показывается вознаграждение, а не объём продаж.

За текущий месяц отображаются накопленные начисления, предыдущие месяцы сохраняются в истории.

Прямо под таблицей: «Итого доступно: … ₽». Это общая доступная сумма вознаграждений за все месяцы за вычетом уже выплаченных сумм и резервов по текущим заявкам на вывод. Месячное «Итого» и доступный сейчас остаток — разные показатели.

## 8. Открытые решения — не выбирать самостоятельно

- Условия открытия, число дополнительных позиций и выбор конкретного вышестоящего партнёра.
- Учёт нескольких позиций одного владельца при подсчёте размера ROOT-структур.
- Первый выбор ROOT при отсутствии сохранённой истории чередования; очередь должна учитываться согласованно при конкурентных регистрациях и откатах.
- Возвраты, частичные возвраты и сторнирование административных начислений; источник их финансирования.
- Границы расчётного месяца, дата отнесения оплаты к месяцу, округление и дата начала действия новых финансовых правил, если они не определены действующими решениями.
- Состав фактически уплаченной суммы для доставки и оплаты внутренним балансом, если действующие правила этого не определяют.
- Надёжная идентификация повторного клиента и связь клиентского закрепления с несколькими позициями владельца.
- Автоматическое создание партнёра из гостевого заказа без отдельного вступления не считается утверждённым этим документом.

Незакрытый вопрос блокирует только зависимую часть реализации, а не весь проект.

## 9. Порядок внедрения и проверок

1. Сверить документацию и код, составить карту расхождений.
2. Внедрить приглашение, закрепление, повторные покупки и переход клиента в партнёры.
3. Обновить балансировку ROOT с проверкой конкуренции и откатов.
4. Внедрить административные начисления после закрытия необходимых финансовых вопросов.
5. Разделить пользователя и позиции, подписки, активность и компрессию; открытие новых позиций включать только после утверждения условий.
6. Собрать финансовый ЛК и доступный остаток без двойного учёта.
7. Провести регрессионные тесты и проверить миграции на отдельной копии базы.

Каждый этап — отдельное проверяемое изменение. Запись в GitHub требует подтверждения конкретного содержимого. Рабочая база, миграции на ней, запуск приложения и выплаты не выполняются автоматически.
